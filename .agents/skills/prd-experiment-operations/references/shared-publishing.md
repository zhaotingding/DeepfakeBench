# 共享发布与归档定位

仅在共享表同步、已授权发布或复用历史实验时读取。记录的是操作方式，不授予push、传输数据、删除分支或整理工作树的权限。

## 显式同步共享ref

已批准执行阶段需要fetch时，使用完整目标引用，避免仅更新FETCH_HEAD却继续读旧的远程跟踪引用：

```sh
git fetch origin refs/heads/codex/prd-progress:refs/remotes/origin/codex/prd-progress
git show origin/codex/prd-progress:PRD实验总表.md
```

共享文档在独立文档工作树修改，不把训练分支合入共享文档分支。先看状态与当前远端，只提交本次相关文档；push后核对远端提交。遇到并发修改时重新同步、检查自己的行及内容，不强推。

来源：2026-10-03/04实际接入记录与PC旧笔记。迁移日期2026-10-15；未在本次重新验证网络。

## PC认证Git与SSH bundle中转

4090直连不可用时，可在已获发布授权的PC文档工作树完成fetch/push，再用Git bundle与SSH把**已发布的共享提交**送入目标仓库；先读取服务器当前共享SHA，以它为基线创建可导入bundle，并在接收端核对依赖与目标提交后更新相应共享ref、读回同SHA。首次缺少基线时再选包含所需历史的bundle。

仅本地提交或bundle传入不等于远端已发布：发布失败时明确记为pending，可放专用handoff引用，不把 `origin/codex/prd-progress` 伪装成已发布。保持凭据留在原认证环境；不要复制token/SSH私钥。网络参数只按当前故障和授权逐命令设置，不将历史代理端口写成项目永久配置。

来源：2026-10多个认领/归档的PC认证bundle及服务器同SHA读回记录，具体任务查共享专属记录。适用于服务器直连失败而PC认证可用的情形；不是对当前网络可用性的保证。
